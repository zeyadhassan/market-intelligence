## 0. Read this first — the five things that will trip you up

1. **`nginx -t` currently FAILS.** The running proxy has a config that no longer validates (`host not found in upstream "nim-qwen7b:8000"`). It serves fine because it hasn't reloaded since the fault appeared. **Any restart or reboot takes the gateway down.** Nothing new can be added until this is fixed.
2. **`sed -i` does not work on bind-mounted config files here.** It writes a new inode and the container keeps seeing the old file. Use `python3` in-place rewrite instead.
3. **Files copied from Windows have CRLF line endings** and fail with `/usr/bin/env: 'bash\r': No such file or directory`. Fix with `sed -i 's/\r$//' file`.
4. **`--cpus` is rejected** — the CPU cgroup controller is not delegated to this rootless user. Use `--memory` only.
5. **NIM containers bind different ports depending on their backend.** vLLM-based: 8000 only. Triton-based: 8000 (OpenAI API), 8001 (gRPC), 8002 (metrics), 8080 (Triton HTTP). This causes port collisions under `--network=host`.

**Total ~564 GB.**

### Interconnect — P2P now works

- 18 NVLinks per GPU × 26.562 GB/s = **~478 GB/s per direction**
- `nvidia-smi topo -m` → NV6 between every pair
- `nvidia-smi topo -p2p r` → `OK` in every direction
- `nvidia-smi nvlink -s | grep -c "26.562 GB/s"` → **72**

**History:** GPU 2 was previously `H200-70C` (half-board, 70 GB, no NVLink, unknown co-tenant). Reprofiled ~9 August. Separately, GPU-to-GPU peer memory access was **disabled at the virtualisation layer**, causing `NCCL WARN Cuda failure 'operation not supported'` on any multi-GPU model. Infrastructure fixed this; confirmed working by NCCL logs showing `Channel NN/0 : 1[1] -> 0[0] via P2P/CUMEM` and `isAllDirectP2p 1`.

**Tensor parallelism is available and in use** (Qwen3-VL at TP=2 across GPUs 2+3).

### vGPU caveats

1. `nvidia-smi utilization.gpu` is unreliable — reports scheduled time share, not SM occupancy. Use serving-layer metrics.
2. Fan, temperature, power, clocks all read `N/A`. `Unable to get power limit for GPU 0` warnings in NIM logs are expected and harmless.
3. Compute is time-sliced, memory hard-partitioned. TP collectives can stall if the hypervisor doesn't schedule slices concurrently — TP *throughput* under vGPU is still unmeasured here.
4. `NVLS multicast support is not available` in NCCL logs is expected under vGPU. Standard P2P still works.
5. **`podman exec <container> nvidia-smi -L` does NOT identify the host slice.** Each container sees its device renumbered as GPU 0. Correlate by UUID or by memory usage.

## 5. Network and registry

### nvcr.io is blocked directly; the proxy works

Direct access returns immediate TCP refusal on every resolved IP. Via proxy it returns `401` with `www-authenticate: Bearer realm="https://nvcr.io/proxy_auth"` — correct.

```bash
export HTTP_PROXY=http://proxy2.cbq.com.qa:3128
export HTTPS_PROXY=$HTTP_PROXY
export http_proxy=$HTTP_PROXY; export https_proxy=$HTTP_PROXY
export NO_PROXY=localhost,127.0.0.1,::1,.cbq.com.qa,10.0.0.0/8
export no_proxy=$NO_PROXY
```

**Session-scoped only.** Not persisted, not inherited by systemd. NIM containers need the proxy passed in explicitly because they fetch model metadata at startup.

### NGC login

Username is the **literal string** `$oauthtoken`. Single-quote it:

```bash
podman login nvcr.io --username '$oauthtoken' --password-stdin < ~/.ngc_key
```

### model-free-nim — the entitlement workaround

`nvcr.io/nim/nvidia/model-free-nim:latest` with `NIM_MODEL_PATH=hf://org/model` and an `HF_TOKEN` pulls weights from Hugging Face, bypassing NVIDIA AI Enterprise entitlement. Also accepts a local path (`/opt/nim/models/...`) for pre-staged weights.

```bash
  nvcr.io/nim/nvidia/model-free-nim:latest
```

**Getting here took six attempts.** Failure history:

| Attempt | Config | Result |
|---|---|---|
| — | `--enable-expert-parallel --quantization awq_marlin`, 32K ctx, util 0.90 | `double free or corruption` in `determine_available_memory()` |
| A | Removed both suspect flags, 32K ctx, util 0.85 | **Same crash** — both flags exonerated |
| D | Added `--enforce-eager --max-num-batched-tokens 8192`, 8K ctx, util 0.80 | **WORKED** |

**The specific cause was never isolated.** D changed four things at once. `--enforce-eager` (disables CUDA graph capture) is the leading suspect since the crash was in a profiling forward pass, but context length 32K→8K is also plausible. Two untested experiments would settle it:
- 8K context **without** `--enforce-eager` → if it works, you get CUDA graphs back and faster inference
- 32K context **with** `--enforce-eager` → if it works, you get long context back

Eager mode costs real throughput, and 8K context is limiting for document OCR. Worth 20 minutes.

## 8. The nginx gateway — port 8443

**This is the most important section for anyone making changes.**

Container `nginx-reverseproxy`, **bridge** networking, on `nim_ai-net` at 10.89.0.6.

| Host file | Container path |
|---|---|
| `/apps/srv_mlengineering/nim/nginx/nginx_router_hybrid_extended.conf` | `/etc/nginx/nginx.conf` |
| `/apps/srv_mlengineering/nim/nginx/router_hybrid_extended.js` | `/etc/nginx/router.js` |
| `/apps/srv_mlengineering/nim/docker_logs/nginx/logs` | `/var/log/nginx` |

### It routes by model name, not URL path

`location / { js_content main.get_backend; }` hands every request to an **njs** script that parses the JSON body, reads `body.model`, lowercases it, and `internalRedirect`s to a named location.

```javascript
function get_backend(r) {
    if (r.method === 'GET') { r.internalRedirect("@_backend_ollama1"); return; }   // ALL GETs → Ollama
    var model = (JSON.parse(r.requestText).model || "").toLowerCase();
    if (model.indexOf("qwen3-vl") !== -1)          { r.internalRedirect("@_backend_qwen3vl"); return; }
    if (model.indexOf("gemma-4") !== -1)           { r.internalRedirect("@_backend_gemma"); return; }
    if (model.indexOf("qwen-2.5-7b-instruct") !== -1) { r.internalRedirect("@_backend_qwen7b"); return; }
    if (model.indexOf("gpt-oss-120b") !== -1)      { r.internalRedirect("@_backend_gptoss120b"); return; }
    // llama-3.3-70b branch is COMMENTED OUT
    r.internalRedirect("@_backend_ollama1");       // default fallback
}
```

**Two consequences to internalise:**

1. **Every GET goes to Ollama.** `GET /v1/models` through 8443 returns Ollama's list, never the NIMs. You cannot verify a NIM via `/v1/models` through the proxy — use a POST.
2. **Unknown model names silently fall through to Ollama** and fail with a confusing error rather than a clear 404. If a call through 8443 behaves oddly, check the match string before assuming the backend is broken.

### Current upstreams

```nginx
upstream backend_ollama1     { server ollama1:11434; }        # container name
upstream backend_gemma       { ... }                          # COMMENTED OUT
upstream backend_qwen7b      { server nim-qwen7b:8000; }      # container name — BROKEN
upstream backend_llama70b    { ... }                          # COMMENTED OUT
upstream backend_gptoss120b  { server nim-gptoss120b:8000; }  # container name
upstream backend_qwen3vl     { server 10.1.94.110:8899; }     # host IP — works
```

### ⚠ `nginx -t` currently FAILS

```
nginx: [emerg] host not found in upstream "nim-qwen7b:8000" in /etc/nginx/nginx.conf:25
```

**Cause:** container-name upstreams depend on podman DNS. `nim-qwen7b` shows `"IPAddress": ""` on `nim_ai-net` — attached in metadata but with no IP, so DNS can't resolve it. nginx only resolves upstream names at startup/reload, so the running process never noticed.

**This is pre-existing, not caused by recent edits.** But it means **any restart or reboot takes the gateway down**, and no new routes can be added until it's fixed.

**Fix — switch container names to host IPs:**

```bash
cd /apps/srv_mlengineering/nim/nginx
cp nginx_router_hybrid_extended.conf nginx_router_hybrid_extended.conf.bak-$(date +%F-%H%M)
python3 -c "
p='nginx_router_hybrid_extended.conf'; s=open(p).read()
s=s.replace('server nim-qwen7b:8000;','server 10.1.94.110:8889;')
s=s.replace('server nim-gptoss120b:8000;','server 10.1.94.110:8897;')
s=s.replace('server ollama1:11434;','server 10.1.94.110:11434;')
open(p,'w').write(s)"
podman exec nginx-reverseproxy sed -n '25p' /etc/nginx/nginx.conf   # verify container sees it
podman exec nginx-reverseproxy nginx -t
podman exec nginx-reverseproxy nginx -s reload
```

**Use `python3`, not `sed -i`.** `sed -i` writes a new inode and breaks the bind mount — the container keeps serving the old file. Always verify with `podman exec ... sed -n '25p' /etc/nginx/nginx.conf` before reloading.

### Adding a new model to the gateway

Three edits: an `upstream` block, a `location @_backend_<name>` line, and an `if (model.indexOf(...))` branch in the JS before the default fallback. A tested script exists at `~/add-embedqa-to-nginx.sh` with backup, `nginx -t` validation, automatic rollback on failure, and `--dry-run` / `--rollback` modes. It auto-detects the `@_backend_` naming convention rather than assuming it.

### No authentication

There is no `auth_basic` anywhere in this config. Port 8443 binds `0.0.0.0`, so every model behind it is callable by anyone on 10.1.94.0/24 with no credential.

## 9. Measured utilisation

From `vllm:cache_config_info` on llama-3.3-70b: `num_gpu_blocks=12,751 × block_size=16` = **204,016 tokens** of KV capacity, `gpu_memory_utilization=0.95`.

Memory ledger, GPU 3: ~70 GB weights + ~65.3 GB KV reservation = 135.3 GB of 141 GB → **`nvidia-smi` reads 96%**.

Traffic, ~10-hour window on 4 August:

```
prompt_tokens_total     504,644
generation_tokens_total   5,040
request_success_total   stop=78  length=20
```

| Metric | Value |
|---|---|
| Requests | 98 (~10/hour) |
| Avg prompt / output | 5,149 / **51** tokens (100:1 prefill ratio) |
| Concurrent capacity | ~39 conversations |
| Observed concurrency | **0.02** |
| Utilisation of reservation | **~0.05%** |
| Prefill throughput | **14 tok/s** (hardware capable of thousands) |
| Queued / preempted | **0 / 0** |

**Key insight: memory reservation is not consumption.** vLLM preallocates at startup regardless of traffic. 96% means "started successfully," not "saturated."

Caveat: single overnight window on a DEV host; may understate weekday peak.

## 12. Operating rules

**Never:**
- `--gpus all` — NVIDIA's own docs recommend it; it lets a container reach any slice including production. Always `--device nvidia.com/gpu=N`.
- `podman system prune -a`, `podman volume prune`, `podman stop -a`, `podman rm -a`, `podman system reset`
- `sed -i` on bind-mounted config files (breaks the mount)
- Reload nginx without a passing `nginx -t`
- Restart another team's container without asking

**Always:**
- `--security-opt=label=disable` (SELinux)
- `--memory` but **not** `--cpus`
- `-d` without `--rm` (a crash should leave logs)
- Baseline before changing: `nvidia-smi`, `podman ps -a`, `podman pod ps`, `ss -tulnp`, `df -h`
- Check free GPU memory *immediately* before launch — Ollama's footprint moves
- Verify config changes landed **inside** the container before reloading
- Use `curl -k https://` for 8443; plain `http://` returns a 400
